# 语音识别 · 模型训练

> 记录语音识别、Core ML、SenseVoice 部署与模型训练相关问答。  
> 涉及：Core ML、Whisper、SenseVoice、FunASR、ONNX Runtime  
>  
> **说明**：本文为技术参考笔记，与当前 App 实现无直接耦合。当前项目使用预训练 SenseVoice INT8，不包含自训练或微调流程。

---

## Q1：语音识别可以使用 Core ML 训练吗？

**A：Core ML 本身不能用于训练，只能用于推理。**

| 环节 | 说明 |
|------|------|
| 训练 | 在服务器端用 PyTorch / TensorFlow 等完成 |
| 转换 | 用 `coremltools` 转为 `.mlmodel` / `.mlpackage` |
| 部署 | 在 iOS / macOS 设备上离线推理 |

**Core ML 能做什么：**
- 在 Apple 设备上运行已训练好的模型
- 利用 CPU / GPU / Neural Engine 加速
- 数据不离开设备，保护隐私

**Core ML 不能做什么：**
- 从头训练语音模型
- 大规模微调（`MLUpdateTask` 仅支持 iOS 15+ 的有限参数更新，不适合 ASR）

**常见方案对比：**

| 方案 | 优点 | 缺点 |
|------|------|------|
| Apple Speech Framework | 系统集成、免费、支持中文 | 不可自定义模型 |
| Whisper Core ML | 离线、可定制、精度高 | 模型体积大、需写 Platform Channel |
| 自训练模型 + Core ML | 完全定制 | 开发成本高、需大量数据 |

**推荐路径：**
1. 需要基础识别 → 直接用 Apple `Speech` 框架（如 `speech_to_text` 插件）
2. 需要离线 + 可定制 → Whisper Core ML + Flutter Platform Channel
3. 需要领域适配 → 服务器端微调 Whisper 后重新转换

## Q2：Core ML 是什么？

**A：Apple 的设备端机器学习推理框架。**

- **只做推理，不做训练** — 模型在服务器端训练好后，转为 `.mlmodel` 部署到设备
- **硬件加速** — 自动利用 Apple 芯片的 CPU、GPU、Neural Engine
- **离线运行** — 数据不离开设备
- **支持多种任务** — 图像识别、NLP、语音处理、目标检测等

> 一句话：**Core ML = 把训练好的 AI 模型放到 Apple 设备上快速运行的工具。**

## Q3：SenseVoice 可以通过 Core ML 放在 iOS 设备上吗？

**A：理论上可以，但实际操作难度较大；更推荐 ONNX Runtime 路径。**

**有利条件：**
- SenseVoice 基于 PyTorch，`coremltools` 支持 PyTorch → Core ML 转换
- SenseVoice-Small 体积相对可控（约 200M+ 参数）

**主要障碍：**
1. **算子兼容性** — 自定义编码器结构等，Core ML 可能不支持部分算子
2. **预处理/后处理** — Fbank 特征提取、tokenizer 解码需单独用 Swift 实现
3. **无官方支持** — 阿里未提供 Core ML 转换方案，社区也无成熟示例
4. **动态形状** — 语音输入长度不固定，Core ML 支持有限

**方案对比：**

| 方案 | 可行性 | 说明 |
|------|--------|------|
| Whisper Core ML | 高 | Apple 官方有示例，社区成熟 |
| SenseVoice + ONNX Runtime | 中高 | 官方支持 ONNX 导出，ONNX Runtime 支持 iOS |
| SenseVoice + Core ML 手动转换 | 中低 | 需自行处理算子兼容与调试 |
| SenseVoice 服务端部署 | 高 | 模型放服务器，客户端调 API，最简单 |

**推荐路径（iOS 离线部署 SenseVoice）：**

```
SenseVoice 导出 ONNX（FunASR 已支持）
        ↓
iOS 端使用 ONNX Runtime Mobile
        ↓
启用 CoreML Execution Provider（利用 Apple 芯片加速）
```

> 本项目 Android 已用 Sherpa-ONNX 跑 SenseVoice；iOS 可参考 Sherpa-ONNX 或 ONNX Runtime Mobile 方案。

## Q4：如何自己训练一个语音识别模型？

**A：整体流程为「数据 → 预处理 → 选架构 → 训练 → 评估 → 部署」，建议从微调现有模型入手，而非从头训练。**

### 整体流程

```
数据收集 → 数据预处理 → 选择模型架构 → 训练 → 评估 → 部署
```

### 硬件与数据

| 规模 | 最低配置 | 推荐配置 |
|------|---------|---------|
| 小型实验 | 单张 8GB GPU | 单张 24GB GPU（如 RTX 4090） |
| 中型训练 | 单张 24GB+ GPU | 多张 A100 |
| 大型训练 | 多机多卡 | GPU 集群 |

**数据量参考：**
- 小型：几十～几百小时标注音频
- 中型：几千小时
- 大型（如 Whisper）：几十万小时

**中文开源数据集：**
- **AISHELL-1** — 170 小时，入门首选
- **AISHELL-2** — 1000 小时
- **WenetSpeech** — 10000+ 小时
- **Common Voice（中文）** — Mozilla 开源
- **THCHS-30** — 30 小时

### 模型架构

| 架构 | 代表模型 | 特点 |
|------|---------|------|
| CTC | DeepSpeech | 简单，适合入门 |
| Attention (Seq2Seq) | LAS | 效果好，需完整输入 |
| CTC + Attention | WeNet, Conformer | 当前主流，兼顾流式与精度 |
| Encoder-Decoder | Whisper | 多语言、多任务 |
| Transducer (RNN-T) | Zipformer | 流式识别首选 |

### 训练框架（从易到难）

1. **HuggingFace Transformers** — 微调 Whisper 几行代码
2. **WeNet** — 中文支持好，工业级
3. **FunASR**（阿里）— SenseVoice 所在框架
4. **ESPnet** — 学术界流行
5. **NeMo**（NVIDIA）— GPU 优化好
6. **Kaldi / Icefall** — 经典，学习曲线陡

### 微调 Whisper 示例

```python
from transformers import WhisperForConditionalGeneration, WhisperProcessor
from transformers import Seq2SeqTrainer, Seq2SeqTrainingArguments

model = WhisperForConditionalGeneration.from_pretrained("openai/whisper-small")
processor = WhisperProcessor.from_pretrained("openai/whisper-small")

training_args = Seq2SeqTrainingArguments(
    output_dir="./whisper-finetuned",
    per_device_train_batch_size=8,
    learning_rate=1e-5,
    num_train_epochs=3,
    evaluation_strategy="steps",
    predict_with_generate=True,
    fp16=True,
)

trainer = Seq2SeqTrainer(
    model=model,
    args=training_args,
    train_dataset=train_dataset,
    eval_dataset=eval_dataset,
    data_collator=data_collator,
)
trainer.train()
```

### 评估指标

核心指标：**CER**（字错误率，中文）/ **WER**（词错误率，英文）

```
CER = (替换 + 删除 + 插入) / 参考文本总字数 × 100%
```

| CER | 评价 |
|-----|------|
| < 5% | 优秀 |
| 5%～10% | 良好 |
| > 15% | 需改进 |

### 部署方式

| 目标平台 | 方案 |
|---------|------|
| 服务端 | PyTorch / TensorRT / Triton |
| 移动端 | ONNX → ONNX Runtime Mobile / Sherpa-ONNX |
| iOS | ONNX Runtime（CoreML EP）或转 Core ML |
| Android | Sherpa-ONNX（本项目方案）或 ONNX Runtime |
| 嵌入式 | Sherpa-ONNX |

### 与本项目的关系

| 需求 | 当前项目做法 | 训练/微调方案 |
|------|-------------|--------------|
| 通用语音识别 | 预训练 SenseVoice INT8 | 一般无需训练 |
| 领域专有词识别 | 热词后处理（见 [热词增加.md](./热词增加.md)） | 低成本，无需改模型 |
| 显著提升某领域精度 | — | FunASR 微调 SenseVoice 后导出 ONNX |
| 替换为自训练模型 | 修改 `model_manager.dart` 下载路径 + 识别器配置 | 需自行转换并测试内存占用 |

### 推荐入门路径

| 阶段 | 时间 | 内容 |
|------|------|------|
| 阶段一 | 1～2 周 | AISHELL-1 + HuggingFace 微调 Whisper-small，跑通全流程 |
| 阶段二 | 2～4 周 | 收集领域数据，微调 + 热词增强，评估 CER |
| 阶段三 | 可选 | WeNet / FunASR 从头训练 Conformer（需 1000 小时+ 数据） |

### 关键建议

1. **先微调，不要从头训练** — 除非有海量数据与算力
2. **数据质量 > 数据数量** — 100 小时干净数据胜过 1000 小时噪声数据
3. **数据增强很重要** — 加噪、变速、混响等提升鲁棒性
4. **先跑通再优化** — 用最简方案先出结果，再逐步改进
5. **移动端部署前测内存** — 参考 [手机压力测试.md](./手机压力测试.md)
