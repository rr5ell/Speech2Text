# 手机压力测试

> 测试目的：评估当前设备在 Flutter + sherpa_onnx + VAD 架构下，可稳定运行的离线 ASR 模型上限。  
> **当前应用版本（2.0.0）仅使用 SenseVoice**，Whisper 相关测试为历史实验记录，供选型参考。

## 当前应用内存占用（SenseVoice）

应用包名：`com.vosk.stt.speech_to_text_vosk`

SenseVoice INT8 模型加载后实测：

| 类型 | 占用 |
|------|------|
| Native Heap（模型推理主要占用） | 443 MB |
| 图形 / UI | 59 MB |
| 其他 | ~47 MB |
| **总计 PSS** | **~549 MB** |

在当前单引擎架构下，SenseVoice（~155 MB 权重）运行稳定。

## 各模型 INT8 权重与运行预估

| 模型 | INT8 权重 | 预估运行时峰值 | 实测结果 | 当前项目 |
|------|-----------|---------------|---------|---------|
| **SenseVoice** | ~155 MB | ~500–600 MB | 正常 | ✅ 使用中 |
| Whisper Base | ~155 MB | ~500–650 MB | 正常（历史） | ❌ 已移除 |
| Whisper Small | ~374 MB | ~800 MB–1.2 GB | **闪退**（历史） | ❌ 已移除 |
| Whisper Medium | ~950 MB | ~1.5–2.5 GB | 不可行 | — |
| Whisper Large | ~1.7 GB | ~3 GB+ | 不可行 | — |

### Whisper Small 闪退原因分析（历史实验）

- 不是下载体积问题（已通过分文件下载解决 610 MB 压缩包解压 OOM）
- 下载完成后，在**加载模型 / 初始化推理引擎**阶段闪退
- Whisper decoder 为自回归结构，推理时需额外 KV cache 与中间缓冲
- Small 相比 Base 多约 **220 MB 权重 + 200–400 MB 推理缓冲**
- 在 Flutter + sherpa_onnx + VAD + UI 叠加下，Native 内存峰值超出稳定阈值

---

## 结论：本机可运行模型上限

```
安全可用上限：  模型权重 ≤ 200 MB（SenseVoice / Whisper Base 级别）
勉强尝试上限：  模型权重 ≤ 400 MB（Whisper Small，当前架构下闪退）
硬件理论上限：  权重 ≤ 800 MB（需原生层深度优化，当前 Flutter 架构做不到）
```

### 对当前项目的含义

1. **SenseVoice（~155 MB）** 是当前架构下的最佳选择，精度与体积平衡良好。
2. 项目已移除 Whisper 双引擎，降低内存占用与维护复杂度。
3. 若需更大模型精度，需考虑云端 API 或原生层深度优化，而非在现有 Flutter 栈上强行加载 Small 及以上。
